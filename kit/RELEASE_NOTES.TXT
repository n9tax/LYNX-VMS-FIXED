Lynx 2.9.3 for OpenVMS VAX  -  release notes
============================================

Built and verified on OpenVMS VAX V7.3, DEC C (Compaq C V6.4),
TCP/IP Services (UCX).  Product name for VMSINSTAL: LYNX293

WHAT IS DIFFERENT FROM STOCK LYNX 2.9.3
---------------------------------------

1.  HTTP works.

    Stock 2.9.3 cannot fetch any http: URL on VMS when built with DEC C.
    HTDoRead() in WWW/Library/Implementation/HTTCP.c line 2534 called
    NETREAD(), which www_tcp.h defines as HTDoRead() -- so the function
    called itself until the stack was destroyed.  The symptom was

        %SYSTEM-F-ACCVIO, access violation ...
        %SYSTEM-F-RADRMOD, reserved addressing fault ...

    with no traceback, on every http: fetch, while local file: rendering
    worked perfectly.  Lynx 2.8.8 called SOCKET_READ() at the equivalent
    line; this build restores that.  Upstream regression.

2.  Build procedure fixes for DEC C on VAX.

    /ACCEPT=NOVAXC_KEYWORDS is now set in build.com, libmake.com and
    build-chrtrans.com.  "readonly" is a VAX C storage-class keyword and
    Lynx uses it as a struct member in src/HTForms.h.

    build-chrtrans.com also passes /DEFINE=(UCX): the LY_SOCKADDR typedef
    in www_tcp.h is unconditional and needs struct sockaddr_in complete.

NOT INCLUDED
------------

    No SSL/TLS.  On its own, https: gives

        Alert!: This client does not contain support for HTTPS URLs.

    Building with OpenSSL on OpenVMS VAX is possible but the practical
    ceiling is OpenSSL 0.9.8, which tops out at TLS 1.0 -- not enough for
    the modern web.  Use a TLS-terminating gateway proxy instead, set in
    lynx.cfg so it covers every user:

        https_proxy:http://yourgateway.example:3128/

    or per session as a process logical (lowercase, so quoted on VMS):

        $ DEFINE "https_proxy" "http://yourgateway.example:3128/"

    IT MUST BE A GATEWAY, NOT A TUNNELLING PROXY.  Lynx sends the proxy a
    plain-HTTP absolute-URI request --

        GET https://host/path HTTP/1.0

    -- and expects the page back in clear.  It never sends CONNECT: that
    code in HTTP.c is inside #ifdef USE_SSL and is not compiled into this
    build.  A stock Squid, which serves https: by tunnelling CONNECT,
    cannot work here.  Check a candidate proxy first:

        printf 'GET https://example.com/ HTTP/1.0\r\n\r\n' | nc HOST PORT

    200 means it will work; 405 or a CONNECT-only answer means it will not.

    Only https: is proxied; plain http: continues to go out directly.

    The online help files (lynx_help) are not in the kit.  Only the VMS
    help text LYNX.HLP is.

KNOWN COSMETIC ISSUE
--------------------

    VMSINSTAL announces the product as "LYNX V29.3" because it parses the
    name as <FACILITY><VVU>.  Display only.

REQUIREMENTS
------------

    OpenVMS VAX V7.3, TCP/IP Services (UCX).
    Lynx_Dir must be defined -- @SYS$MANAGER:LYNX$STARTUP does it.

MAKING LYNX AVAILABLE TO ALL USERS
----------------------------------

    Add  $ @SYS$MANAGER:LYNX$STARTUP  to BOTH of these:

        SYS$MANAGER:SYSTARTUP_VMS.COM   defines Lynx_Dir /SYSTEM at boot,
                                        so every process sees it.
        SYS$MANAGER:SYLOGIN.COM         defines the LYNX command.  DCL
                                        symbols are per-process and cannot
                                        be made system-wide, so this must
                                        run in every user's login.

    Doing only one of the two is what leaves Lynx working for the account
    that installed it and no one else.

BOOKMARKS AND THE START PAGE
----------------------------

    Every user gets their own bookmark file, SYS$LOGIN:lynx_bookmarks.html,
    with no setup.  Lynx prepends the home directory to
    DEFAULT_BOOKMARK_FILE, so that setting must stay a BARE FILENAME; an
    absolute path there gives the whole system one shared file.

    Note that "BOOKMARK_FILE" is NOT a lynx.cfg keyword.  Only
    DEFAULT_BOOKMARK_FILE exists; a BOOKMARK_FILE line is silently ignored.

    A user's own bookmarks are their start page.  SYS$MANAGER:LYNX$STARTUP
    defines WWW_HOME at login pointing at their bookmark file, and Lynx's
    precedence is:  command line > WWW_HOME > STARTFILE.  So bookmarks are
    the default page and "LYNX <url>" still works.

    Do NOT use "LYNX -book" to get this.  -book also overrides a URL given
    on the command line, so "LYNX http://host/" would open bookmarks
    instead.

    On a user's first login the startup procedure copies an empty bookmark
    file into their SYS$LOGIN from Lynx_Dir:LYNXBOOK.HTML.  That is what
    makes the FIRST bookmark appear on the start page straight away; the
    procedure runs before the user has any bookmarks, so without the seed
    the start page would only switch over at their next login.

    THE BOOKMARK FILE MUST BE STREAM_LF.  Lynx appends a bookmark by
    reopening the file "a+", rewinding and re-reading it.  On a
    variable-length record file that read returns nothing, Lynx decides the
    file is new, and writes a SECOND copy of the whole header.  DCL CREATE,
    OPEN/WRITE and COPY from a text file all produce variable-record files;
    Lynx itself writes Stream_LF.  The skeleton is therefore converted at
    kit-build time with CONVERT/FDL, and every step after that preserves the
    record format.  If you hand-make a bookmark file, check it with
    DIRECTORY/FULL -- "Record format: Stream_LF" is what you need.

    Until a user has any bookmarks they get STARTFILE, which this kit sets
    to a local page installed as SYS$COMMON:[LYNX]LYNXSTART.HTML.  The
    upstream default is an https: URL and cannot work without SSL.

    Any page used as a start page must be World:RE.  A page without world
    access gives "Can't access startfile" -- that message is far more often
    a protection problem than a URL syntax problem.
